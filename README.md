# REVODIX Workspace V4 — 무료 독립형 견적·발주 업무보드

`index.html`을 열면 표·칸반·일정으로 관리하는 업무보드가 바로 열립니다. monday.com 방식의 주요 업무 관리 동작을 독립적으로 구현했습니다. monday.com 자체 제품이나 모든 기능을 복제한 서비스는 아닙니다.

**기본 실행에 유료 구독, monday.com 계정, API 토큰, Node.js, 서버 설치가 필요 없습니다.** 공개 GitHub에는 코드만 있으며 회사 실적은 별도 제공한 실행 ZIP에만 포함됩니다.

## 실행 (Windows)

1. ZIP을 다운로드하고 **모두 압축 풀기**를 누릅니다.
2. 폴더의 **index.html** 또는 **Start.cmd**를 더블클릭합니다.
3. 첫 화면에서 **견적 관리 / 발주 관리 / 내 업무**를 선택합니다.
4. GitHub 코드만 받은 경우 **파일 묶음 불러오기**로 엑셀을 선택하거나 **백업 복원**으로 기존 V2/V2.1/V3 JSON을 엽니다. 실제 실적 포함 배포본은 처음 첨부한 자료가 열립니다.
5. 예전 프로그램에서 보정한 값이 있다면 그 프로그램에서 **데이터 백업** 후 새 버전에서 **백업 복원**으로 불러오세요.

기존 V3의 monday 연동 코드는 개발 참조용으로 보존했지만 V4 기본 화면에서는 실행하지 않습니다. 예전 API 서버나 Start_Monday.cmd는 이 독립형 사용에 필요하지 않습니다. [V3 연동 설명](docs/monday-integration-v3.md)은 이전 버전 참고 자료입니다.

## 업무보드 사용

| 기능 | 사용 방법 |
|---|---|
| 표에서 직접 수정 | 담당자·메이커를 입력하고 **Enter** 또는 다른 칸으로 이동. 상태·우선순위·예정일을 선택합니다. |
| 상세 / 메모 | 항목 제목 또는 **메모 / 상세**를 눌러 정보를 수정하고 저장합니다. |
| 여러 행 상태 변경 | 체크박스로 선택 → 진행 상태 선택 → **선택 행에 적용**. 페이지당 40행입니다. |
| 칸반 | 상단 **칸반** 선택. 카드를 다른 상태로 끌어 옮기거나 상세에서 상태를 바꿉니다. 각 상태는 처음 25개 표시하고 더 볼 수 있습니다. |
| 일정 | **일정** 선택. 기본은 직접 지정한 업무 예정일이며 **원본 문서일**로 바꿔 볼 수 있습니다. **자료가 있는 달**은 해당 기준의 최근 자료가 있는 달로 이동합니다. |
| 달력의 여러 항목 | **더 보기**를 누르면 해당 날짜의 항목을 표로 모아 보여 줍니다. 검색 초기화로 날짜 제한을 해제합니다. |
| 새 업무 | **＋ 새 업무**로 별도 연락·확인·할 일을 만듭니다. **내 업무**에서 관리하며 견적·발주 실적 금액에 합산하지 않습니다. |
| 업무 보관 | 직접 만든 업무의 상세 → **업무 보관**. 원본 실적은 보관/삭제하지 않습니다. |
| 취소 | **직전 변경 취소**로 이 실행 중 업무보드 변경을 최근 10회까지 되돌립니다. 자료 교체·재실행 시 취소 내역은 초기화됩니다. |
| 검색 / 분류 | 연도·담당자·메이커·진행 상태·우선순위 및 문서번호·거래처·품번·메모 검색. 표는 상태·담당자·메이커로 묶어 볼 수 있습니다. |
| 파일로 내보내기 | 업무보드 조회 결과는 CSV, 전체 자료는 상단 **데이터 백업**으로 JSON 저장합니다. |

상태는 **미분류 / 검토 중 / 후속 연락 / 협의 중 / 완료 / 보류**입니다. 원본 실적 파일에 업무 진행 상태가 없으므로 임의로 수주 여부를 추정하지 않고 모두 미분류로 시작합니다. 상태는 사용자가 정하는 후속 업무 관리용입니다. 완료 항목 수를 견적→발주 전환율로 해석하지 않습니다.

담당자 초기값은 원본 작성자입니다. 변경하면 담당자별 분석에도 반영되며 원래 담당자·메이커는 기존 보정 정보로 보존합니다. 원본 금액·문서번호·날짜·총 문서 건수는 바꾸지 않습니다. 같은 문서의 다른 품목 행이나 대응 견적·발주에는 자동 전파하지 않습니다.

표·칸반·일정은 동일한 자료를 사용합니다. 일정은 알림 발송이나 외부 캘린더 연결 기능이 아니며 표시·관리용입니다. [기존 분석 기준](docs/analysis.md)에 3개년 동기간 비교와 중복 원본 처리 기준을 설명했습니다.

## 자동 저장과 백업

- 변경 내용은 브라우저의 IndexedDB에 저장합니다. **이 PC에 자동 저장됨** 표시를 확인하세요. **지금 저장**으로 즉시 저장할 수 있습니다.
- **같은 PC·브라우저·폴더 경로**에서 다시 열면 자동 저장본을 먼저 복원합니다. 같은 경로의 첨부 초기 자료보다 자동 저장본이 우선합니다.
- 브라우저의 파일 접근/저장 정책, 시크릿 모드, 저장 공간에 따라 자동 저장이 막힐 수 있습니다. 실패하면 배지가 **파일 백업 필요**로 표시됩니다. 이때 **데이터 백업**을 저장하고 다음 실행에서 복원하세요.
- 폴더를 옮기거나 다른 PC/브라우저로 이동할 때, 브라우저 데이터를 삭제하기 전에는 반드시 JSON 백업을 저장하세요. 자동 저장은 회사 서버에 보관하는 백업이 아닙니다.
- 백업에는 실적, 실제 담당자·메이커 보정값, 상태·우선순위·예정일·메모, 직접 만든 업무가 함께 포함됩니다. 회사 실적 포함 JSON을 공개 GitHub에 올리지 마세요.
- 예시 데이터에서는 PC 자동 저장을 하지 않습니다. 실제 자료 자동 저장본을 예시로 덮어쓰지 않기 위한 동작입니다.
- 엑셀 재불러오기와 첨부 자료 다시 열기는 전체 자료를 교체합니다. 업무 메모가 자동으로 새 파일에 이어 붙는 기능은 없으므로 먼저 백업해 주세요.

## 지원 범위

이 버전은 한 PC에서 사용하는 독립형 업무 도구입니다. 직원 간 실시간 공동 편집, 계정별 권한, 서버 동기화, 이메일 알림, monday.com 유료 자동화 전체 기능은 제공하지 않습니다. 여러 사람이 파일을 각각 열면 서로 다른 사본을 사용하게 됩니다.

## 검증 및 코드

`work-model.js`는 품목별 업무 상태·일정·메모 및 직접 만든 업무를 관리하고, `work-ui.js`는 표·칸반·달력과 IndexedDB 저장을 담당합니다. 기존 엑셀·분석·보정 코드를 함께 유지합니다.

Node.js가 있는 개발 환경에서 자동 테스트를 실행할 수 있습니다. 사용자 실행에는 설치가 필요하지 않습니다.

```sh
npm test
```

검증 범위: 품목별 수정·일괄 수정, 날짜 유효성, 금액/건수 유지, 원본 담당자 보존, 새 업무 분리, 보관/취소, 백업 직렬화. 브라우저에서도 업무 생성·담당자 변경·일정 표시·재실행 자동 복원을 확인했습니다.

ZIP을 모두 푼 폴더와 vendor 파일을 함께 보관하세요. JSZip의 라이선스는 `vendor/LICENSE-JSZip.txt`에 포함되어 있습니다.
