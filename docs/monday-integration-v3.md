# REVODIX 견적·발주 분석 V3 — monday.com 연동

3개년 엑셀 분석과 실제 담당자·메이커 보정 기능에 monday.com 데이터 가져오기·선택 전송을 추가한 PC용 프로그램입니다.

**이 공개 저장소에는 코드만 있습니다. 회사 실적과 API 토큰은 포함하지 않습니다.** 이전 V2/V2.1에서 저장한 JSON 백업을 복원하거나 원본 엑셀을 불러오세요. 별도 제공된 실제 실적 포함 ZIP에서는 처음 첨부한 실적이 열립니다.

## 처음 실행하기 (Windows)

1. GitHub의 **Code → Download ZIP**을 누르고 **모두 압축 풀기**를 선택합니다.
2. [Node.js 공식 사이트](https://nodejs.org/)에서 **22 이상 LTS 버전**을 설치합니다. 별도 npm 패키지는 설치하지 않습니다.
3. 폴더의 **Start_Monday.cmd**를 더블클릭합니다. 서버 창을 열어 둡니다.
4. 브라우저에서 `http://127.0.0.1:8731`이 열립니다. 처음 실행에 페이지가 열리지 않으면 서버 창의 주소를 열어 주세요.
5. **백업 복원**으로 기존 V2/V2.1 자료를 가져옵니다. 원본 엑셀을 함께 선택하여 불러와도 됩니다.
6. 왼쪽 **monday.com 연동**에서 아래 설정을 진행합니다.

엑셀 분석만 할 때는 기존처럼 `index.html` 또는 `Start.cmd`를 열 수 있습니다. 실제 API 연동은 `Start_Monday.cmd`로 실행해야 합니다. Mac/Linux는 Node.js 22 이상에서 `npm start`를 실행하세요.

## monday.com 연결

ChatGPT의 monday.com 플러그인 연결과 이 PC 프로그램의 API 연결은 **별개**입니다. 플러그인의 인증 정보를 코드로 복사하지 않습니다.

1. monday.com 계정에서 개발자용 **개인 V2 API 토큰**을 발급합니다. 계정에서 발급이 허용되지 않으면 관리자에게 문의하세요. [공식 발급 설명](https://developer.monday.com/api-reference/docs/authentication)
2. 프로그램의 비밀번호 입력칸 **개인 API 토큰**에 입력하고 **연결 확인**을 누릅니다. 토큰은 대화창·GitHub·코드에 넣지 마세요.
3. **보드 목록 조회 → 보드 선택 → 보드 열 조회**를 누릅니다. 목록은 100개 단위로 다음 페이지를 조회할 수 있습니다. 보드 ID를 직접 입력해도 됩니다.
4. **견적 / 발주** 종류를 선택하고 실제 보드의 열을 각각 연결합니다. 견적과 발주는 별도 보드를 사용하세요. 한 보드에서 종류별 행 필터로 나누는 방식은 지원하지 않습니다.
5. **연결 설정을 백업 자료에 포함**을 누른 후 상단 **데이터 백업**을 저장합니다. 보드·열 ID와 담당자 연결은 백업되며 토큰은 백업되지 않습니다.

| 프로그램 항목 | monday.com 열 형식 | 필수 여부 |
|---|---|---|
| 문서번호 | 텍스트 | 필수. 같은 문서에 여러 품목 행이 있어도 됩니다. |
| 날짜 | 날짜 | 필수. 문서번호의 연도 대신 실제 날짜를 사용합니다. |
| 금액(원) | 숫자 | 필수. 행별 합계 금액이며 수량을 다시 곱하지 않습니다. |
| 거래처 | 텍스트 | 필수. 사업장/법인 거래처를 연결합니다. |
| 실제 담당자 | 텍스트 또는 People | 필수 |
| 메이커 | 텍스트 | 필수. 대문자로 통일합니다. |
| 외부 연동키 | 텍스트 | 엑셀 자료 신규 등록 시 필수. 보드에서 전용 열을 미리 만드세요. |
| 품번·제품명·영업팀·응용분야·거래방식 | 텍스트 (제품명은 긴 텍스트도 가능) | 선택 |
| 수량 | 숫자 | 선택 |

같은 열을 여러 항목에 중복 연결할 수 없습니다. 이름 열(name)은 문서번호 텍스트 열을 대신하지 않습니다. 필요한 열과 보드는 monday.com에서 먼저 만들어 주세요. 프로그램이 보드·열을 자동 생성하거나 구조를 변경하지 않습니다.

담당자를 People 열에 연결하면 **사용자 목록 조회** 후 각 이름에 해당하는 사용자 ID를 명시적으로 지정합니다. 동명이인을 이름만 보고 자동 매칭하지 않습니다. 이 버전은 신규 담당자로 1명을 지정하며, 기존 복수 담당자·팀 지정 전체를 그 사람으로 교체합니다. 담당자를 수정하지 않으면 기존 People 값은 그대로 둡니다.

## 가져오기: monday.com → 분석

1. 대상 보드·열을 연결한 뒤 **가져오기 미리보기**를 누릅니다.
2. 유효 행 수, 오류 제외 행 수, 대상 보드와 처음 20행을 확인합니다.
3. **검토한 자료로 교체**를 누르면 현재 자료 중 선택한 종류(견적 또는 발주) **전체**를 교체합니다. 다른 종류는 유지합니다. 먼저 기존 자료를 백업하세요.
4. 문서번호·날짜·금액이 없는 행은 제외됩니다. 제외 사유를 미리보기와 자료 점검에서 확인할 수 있습니다.
5. 상단 데이터 백업으로 저장합니다.

일반 활성 항목만 읽습니다. 보관·삭제 항목, 하위항목, 계층형 보드의 하위 데이터, 상태·드롭다운·미러·수식·연결보드 열은 지원 범위에 포함하지 않습니다. API 페이지를 끝까지 읽되 보드당 100,000행을 초과하면 중단합니다.

## 전송: 분석 → monday.com

1. **담당자·메이커 설정**에서 종류·연도·거래처 등으로 검색하고 전송할 품목 행을 체크합니다.
2. **monday.com 전송 검토**를 누릅니다. 한번에 **같은 종류의 최대 50행**을 선택하세요.
3. 대상 보드·열을 연결하고 **선택 행 전송 검토**를 누릅니다. 이 단계는 조회만 하고 쓰지 않습니다.
4. 보드 이름·ID와 각 행의 신규 등록/수정/기등록/변경 없음 구분, 반영 필드를 확인합니다.
5. 확인 체크 후 **검토한 내용 실제 전송**을 누릅니다. 검토는 5분 후 만료됩니다.
6. 처리 결과의 항목 ID를 확인합니다. 다음 수정 전에는 보드에서 다시 가져와 최신 원격 값과 항목 ID를 읽으세요.

| 행의 출처 | 전송 동작 |
|---|---|
| monday.com에서 가져온 행 | 원래 보드·항목 ID로 **실제 담당자·메이커 변경값만** 업데이트. 원격 금액·날짜·거래처는 바꾸지 않습니다. |
| 엑셀에서 가져온 행 | 지정 보드의 일반 항목으로 연결한 필드를 신규 등록. 원본 출처·행·문서번호·날짜·품번으로 외부 연동키를 생성합니다. |
| 같은 연동키가 이미 보드에 있는 엑셀 행 | 기존 등록으로 표시하고 다시 만들거나 덮어쓰지 않습니다. 수정하려면 보드에서 다시 가져온 후 변경하세요. |
| 원격에서 담당자·메이커가 변경된 행 | 가져온 당시 값 및 검토 후 재조회와 비교하여 전송 중단. 백업 후 다시 가져와 비교하세요. |

문서번호만으로 견적과 발주를 연결하거나 다른 품목 행에 수정값을 전파하지 않습니다. 원견적번호가 없어 견적→발주 전환율은 추정하지 않습니다. 생성/업데이트 결과를 로컬 원본에 자동 덮어쓰지 않으며 보드에서 다시 읽어 최신 상태를 확인합니다.

## 오류와 제한

- 한 번 검토한 계획은 한 번만 실행할 수 있습니다. 전송은 순서대로 하며 오류가 나면 확인된 성공 행까지만 표시하고 멈춥니다. 보드 쓰기는 전체 트랜잭션/롤백을 지원하지 않습니다.
- 타임아웃 중 신규 등록이 성공했는지 불확실할 수 있습니다. 자동 재시도하지 않습니다. 원격 보드를 확인하고 다시 검토하면 활성 항목의 외부 연동키를 확인합니다.
- 외부 연동키에 고유 제약을 걸지는 못하므로 여러 PC/사람이 동시에 등록하면 중복이 발생할 수 있습니다. 보관·삭제된 항목의 키도 검색하지 않습니다. 원본 파일 구성이 달라지면 출처 식별자가 달라질 수 있어 재수입 자료의 키도 달라질 수 있습니다.
- 검토 후 전송 직전 재검사를 하지만 monday.com에 조건부 원자 업데이트를 요청하는 구조는 아닙니다. 다른 사용자와 동시에 같은 항목을 수정하지 마세요.
- 전송 중에는 연결 설정과 자료를 바꾸지 말고 창을 열어 두세요. API 사용량·복잡도·일일/분당 제한이나 보드 권한에 따라 요청이 중단될 수 있습니다.
- 토큰은 Node 프로세스 메모리에만 보관하며 서버 종료·연결 해제 시 프로그램에서 제거합니다. 환경변수 `MONDAY_API_TOKEN`으로 시작할 수도 있습니다. `.env`는 자동으로 읽지 않습니다.
- 서버는 `127.0.0.1`에만 열리며 외부 배포/공유 서버 용도가 아닙니다. 공개 GitHub Pages에서는 실제 API 연동이 동작하지 않습니다.

## 확인한 범위

합성 응답을 사용하는 자동 테스트로 페이지네이션, 타입별 변환, 중복키, People ID, 검토/실행 분리, 원격 충돌, 일부 실패, 토큰 비노출, 로컬 접근 제한을 검증합니다. 실제 계정의 권한·요금제·열 구조·실제 쓰기 성공 여부는 사용자 계정으로 연결한 뒤 확인해야 합니다. 테스트는 실제 보드나 회사 데이터를 수정하지 않습니다.

```sh
npm test
```

주요 파일: `server.cjs`(로컬 서버), `monday-api.cjs`(공식 API 호출), `monday-core.cjs`(변환·전송계획), `monday-ui.js`(연동 화면). 기존 분석 및 보정 코드는 함께 포함되어 있습니다. 자세한 통계 기준은 [분석 기준](docs/analysis.md)을 참고하세요.

공식 API 근거: [인증](https://developer.monday.com/api-reference/docs/authentication), [버전](https://developer.monday.com/api-reference/docs/api-versioning), [항목](https://developer.monday.com/api-reference/reference/items), [페이지](https://developer.monday.com/api-reference/reference/items-page), [다음 페이지](https://developer.monday.com/api-reference/reference/next-items-page), [People](https://developer.monday.com/api-reference/reference/people). 기본 API 버전은 `2026-10`이며 필요하면 환경변수 `MONDAY_API_VERSION`으로 지정합니다.
