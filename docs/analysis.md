## V2.1 추가: 실제 담당자·메이커 설정

1. 왼쪽 **담당자·메이커 설정** 또는 상단 같은 이름의 버튼을 누릅니다.
2. 종류·연도·거래처·현재 담당자·메이커·문서번호·품번으로 대상을 찾습니다. 이 화면의 검색 조건은 분석 화면 필터와 별개입니다.
3. 한 행의 **설정**을 눌러 실제 담당자와 메이커를 입력합니다. 기존 이름 선택과 새 이름 직접 입력을 모두 지원합니다. 빈 입력칸은 기존 값을 유지하며 메이커는 대문자로 통일합니다.
4. 여러 행은 체크박스로 선택하고 **선택 항목 일괄 지정**을 누릅니다. **검색 결과 전체 선택**은 현재 검색에 걸린 모든 페이지의 행을 선택합니다. 검색 조건을 바꾸면 선택이 해제됩니다.
5. 적용 전 대상 행 수와 변경 예정 행 수를 확인합니다. 같은 문서번호여도 선택한 품목 행만 수정합니다. 견적·발주를 자동 연결하거나 수정값을 전파하지 않습니다.
6. 분석과 담당자·메이커 필터는 변경값으로 다시 계산됩니다. 금액·날짜·문서번호·총 건수와 원본 엑셀은 바꾸지 않습니다. 수정한 행에는 원본 담당자·메이커가 표시됩니다.
7. **직전 변경 취소**는 현재 실행 중 마지막 수정 1회를 취소합니다. 자료 교체·백업 복원·재실행 시 취소 기록은 초기화됩니다.
8. 종료 전 **데이터 백업**을 저장하고, 다음 실행에서 **백업 복원**으로 여세요. 수정값과 원본값이 함께 보관됩니다. 브라우저에 자동 저장하지 않습니다. 새 엑셀 불러오기와 첨부 자료 다시 열기는 자료 전체를 교체하므로 수정값을 자동 이월하지 않습니다.

GitHub의 코드는 실제 담당자 배정표를 포함하지 않습니다. 실제 담당자는 사용자가 지정하며, 최초 값은 원본의 작성자입니다. 기존 V1/V2 백업도 복원할 수 있습니다.

검증: `node tests/model.test.cjs`, `node tests/erp.test.cjs`, `node tests/assignments.test.cjs`

# 3개년 견적·발주 분석 v2

ERP에서 내려받은 견적·발주 원본을 바탕으로 기준연도와 앞선 2개년을 비교하는 PC용 분석 프로그램입니다.

## 실행 방법

1. GitHub 저장소의 **Code → Download ZIP**을 누릅니다.
2. **모두 압축 풀기**를 합니다.
3. 폴더 안의 **index.html** 또는 Windows의 **Start.cmd**를 더블클릭합니다.
4. **파일 묶음 불러오기**에서 견적·발주 XLSX 파일을 함께 선택하고 **현재 자료 전체 교체**를 누릅니다.

이 저장소에는 회사 실적을 넣지 않습니다. 실적을 포함한 별도 배포본에서는 `private-data.js`를 통해 첨부된 실적이 시작할 때 열립니다. GitHub 다운로드본은 자료가 없는 상태로 시작하며, 파일을 불러오거나 **예시 보기**로 기능을 확인할 수 있습니다. `private-data.js`, 원본 엑셀, 실적 백업은 Git에 올리지 않도록 `.gitignore`에 제외했습니다.

## 3개년 비교

- 기준연도와 이전 2개년의 견적금액, 견적 건수, 발주금액, 발주 건수를 표시합니다.
- **같은 기간 비교**가 기본입니다. 기준연도 견적·발주 중 제공된 말일이 더 이른 자료를 기준으로 비교 종료일을 맞춥니다.
- 예를 들어 기준연도 파일이 9월 30일까지라면 과거 연도도 같은 월·일까지 비교합니다. 윤년의 2월 29일은 해당 연도의 마지막 날짜에 맞춥니다.
- **연간 전체 비교**는 연도별 제공 자료를 전부 합산합니다. 미마감 연도와 마감 연도는 집계 범위가 다를 수 있음을 표시합니다.
- 월별 추이에서 자료 미제공 월은 빈칸으로 표시합니다. 제공 기간 안에서 거래가 없는 경우는 0입니다.
- 담당자(작성자), 거래처, 메이커, 영업팀, 응용분야, 거래방식별로 필터링합니다.
- 거래처·메이커 등 분류별로 3개년 금액, 증감금액과 증감률을 보여줍니다.
- 연도 비교, 분류 분석, 실적 상세를 CSV로 저장할 수 있습니다.

## 원본 열의 의미

| 원본 열 | 분석 항목 | 처리 기준 |
|---|---|---|
| 사업장 | 거래처 | 개인 고객명 대신 거래 회사명 사용 |
| 견적일 / 발주일 | 실제 거래일 | 문서번호에 포함된 연도와 무관하게 실제 날짜로 분류 |
| 견적번호 / 발주번호 | 문서번호 | 같은 문서의 여러 품목은 건수 1건 |
| 브랜드 | 메이커 | 앞뒤 공백을 정리하고 영문 대문자로 통일 |
| T/P(원) | 행별 금액 | 합산만 하며 수량을 다시 곱하지 않음 |
| 견적 작성자 | 작성자 | 실제 영업 소유자와 다를 수 있으므로 원본 작성자 기준임을 명시 |
| 뒤쪽 부서 | 영업팀 | 앞쪽 고객 소속 부서와 구분 |
| 응용분야 | 응용분야 | 원본 분류 유지 |
| 거래방식 | 거래방식 | 원본 분류 유지 |

전화번호, 주소, 개인 고객명은 분석 레코드에 담지 않습니다. 원가·프로젝트 항목은 연도별 열 구성이 다르므로 현재 주 비교 범위는 견적·발주 금액과 문서 건수입니다.

## 중복 및 원본 점검

- 견적·발주 원본 열이 있는 시트를 자동으로 찾습니다. 원본 열이 없는 피벗·요약 시트는 제외합니다.
- 분석에 쓰는 정규화된 행 전체가 같은 시트는 한 번만 반영하고 원본 파일명을 점검 화면에 남깁니다.
- 서로 다른 원본 시트에 문서번호가 겹치면 부분 중복 가능성을 표시합니다. 동일한 품목 행을 임의로 삭제하지 않습니다.
- 값 없는 서식 행은 XML 파싱 전에 제거합니다. 백만 행에 서식이 적용된 파일도 유효 데이터 위주로 처리합니다.
- 문서번호·날짜·금액이 유효하지 않으면 제외하고 목록을 제공합니다.
- XLSX / CSV, 파일당 30MB, 자료 종류별 백업 최대 100,000행을 지원합니다. 암호 파일, XLS, XLSB는 지원하지 않습니다.
- 수식은 실행하지 않고 저장된 계산 결과를 읽습니다. 결과가 없는 수식은 원본에서 값으로 붙여넣어 주세요.
- 통화·부가세 포함 여부와 취소·변경 이력은 원본 기준입니다. 단위를 혼합하거나 변경 견적의 이전 버전을 함께 넣지 않도록 원본을 확인해 주세요.

## 전환율과 금액 비율

제공 원본에 원견적번호 연결 열이 없으면 실제 견적→발주 전환 여부를 확정할 수 없습니다. 따라서 v2의 기본 화면은 전환율 대신 동기간 금액·건수와 증감률을 표시합니다. 문서번호가 비슷하다는 이유로 추정 연결하거나 발주금액/견적금액을 전환율로 표시하지 않습니다.

증감률은 `(현재 − 전년) / 전년`입니다. 전년 값이 0 이하이거나 자료가 없으면 표시하지 않습니다.

## 데이터 보관

- 네트워크 요청은 차단하며 실적 파일을 외부 서버나 GitHub에 전송하지 않습니다.
- 새로 불러온 자료는 현재 브라우저 창에 있습니다. 종료 전에 **데이터 백업**을 저장합니다.
- 실적 포함 별도 배포본은 다시 열면 최초 첨부 데이터가 열립니다. 추가로 불러온 자료는 백업으로 복원할 수 있습니다.
- 파일 묶음을 적용하면 현재 자료 전체를 교체합니다. 무조건 누적해서 중복 집계하지 않습니다.
- v1 및 v2 JSON 백업을 복원할 수 있습니다. v1에 없던 세부 분류는 미기재로 표시합니다.

## 코드

- `index.html`, `style.css`: 대시보드와 화면 디자인
- `app.js`: 파일 묶음 가져오기, 필터, 화면, 내보내기
- `erp-model.js`: ERP 열 매핑, 중복 시트 판정, 비교 기간과 3개년 집계
- `model.js`: 금액·날짜·문서 건수와 CSV 공통 처리
- `workbook.js`: XLSX/CSV 읽기, 서식 전용 빈 행 정리
- `vendor/jszip.min.js`: 로컬 ZIP 처리
